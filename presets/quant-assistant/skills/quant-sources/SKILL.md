# 数据来源与覆盖边界

## 一句话原则

**所有数据都在本地**（`$DSH_HOME/quant/quant.db`）。网络只用于同步，不用于计算。
因此：**回答任何量化问题前先看 `quant_data_status`** —— 数据没同步或过期时，后面所有结论都不可信。

## 来源与分工

| 数据 | 来源 | 说明 |
|---|---|---|
| 日线行情（不复权） | 东财 `push2his` 为主，**新浪为兜底** | 新浪序列已与 BaoStock 独立源逐字节比对一致 |
| 复权事件 | 东财分红送转 + 腾讯事件元数据，**离线表优先** | 见下"离线事件表" |
| 代码表 | 东财 `clist`（含退市股） | ST 由名称推断；上市日需其他来源补 |
| 基本面 | 东财数据中心 `RPT_LICO_FN_CPD` | 报告期快照 + 公告日生效，**不做财报重述回溯** |
| 实时行情 | 东财 `push2` | 仅 `quant_quote` 用；有速率限制 |

**为什么必须有兜底**：东财 `push2*` 家族在约 300 次探测后会被 IP 封禁（实测 0/5 成功）。
http 层做了内容校验（不是状态码）、重试退避与熔断（阈值 8 次、冷却 120 秒）。
被封时新浪兜底能继续工作，所以同步不会因为单一来源挂掉而全盘失败。

## 已知覆盖边界（八条，必须主动告知用户）

1. **代码表覆盖沪深北 A 股（含已退市的 A 股），不含三板/代办股份。**
   退市股没有单独板块，仍在原市场段里，只是不再更新行情。
   当前代码表实测 5923 只，其中名称含「退」的 154 只。
   **不要说"全市场"就等于"所有股票"**——三板（400xxx）不在范围内。
2. **退市股的复权事件不全。** 退市后数据源停止更新分红记录，历史事件可能有缺口。
3. **同日多笔分配可能被来源合并。** 实测 300750 在 2024-04-30：东财只记 2.011，实际合计 5.01。
   离线表已固化已发现的修正；**包发布之后新发生的**同日多笔分配由运行时规则处理，
   无法仲裁时标记 `unresolved`（宁可不猜）。
4. **存在所有事件源都漏记的分配。** 实测 300750 在 2025-01-24 的官方涨跌幅与不复权收益
   相差 0.49pp，说明当日有一次分配，但东财、腾讯、BaoStock 的分红数据里都没有。
   这类日期无法由离线表覆盖，**只能靠官方涨跌幅对账发现**。
5. **个别标的原始价序列存在一日错位风险。** 实测 601899 在 2018-06-25/26 出现连续两天、
   方向相反的各 0.26pp 偏差，是典型的"序列错位一天"特征。
6. **停牌与涨跌停按日线判定。** 日频无法区分"盘中先冲高再回落"，止损类规则使用显式假设。
7. **基本面不做重述回溯。** 财报修正不会回填历史。
8. **北交所代码的市场归属待复核。** 东财 market=0 的假设未用真实样本验证。

完整版见仓库的 `DATA-SOURCES.md`。

## 离线事件表

`data/factor-events.json.gz` 随包发布（约 1.6KB，168 个事件 / 13 只股票），
只存**已确认的复权因子**，用于覆盖上述第 3、4 条的缺口。

- 它**按股票代码生效**（早期版本曾对每只股票都套用，是 bug）
- 优先级：**离线表 > 运行时合并结果**（离线表是人工核对过的）
- 覆盖面有限：只在已发现的缺口上权威，不是全市场事件表

## 复权口径（最容易出错的地方）

- **因子与收益一律算在复权价上**（`bars_adj` 视图）。否则动量类因子会在除权日带上
  分红跳空，产生假信号。
- **涨跌停与停牌判定一律用原始价**（`bars` 表）。用复权价判断会算错涨跌停幅度。
- 参考价公式：`ref = round((前收盘 − Σ现金) / (1 + Σ送股 + Σ转增), 2)`，`factor = 前收盘 / ref`。
  交易所参考价**四舍五入到分**，这一步不能省。

## 没有专用工具时怎么兜底

v1 有意**不做**新闻/研报/资金流的专用抓取工具（见架构 §6）。这些数据用 `web_fetch` 直接取：

- 东财板块/资金流接口：`push2.eastmoney.com/api/qt/clist/get`
- 个股资金流：`push2.eastmoney.com/api/qt/stock/fflow/kline/get`
- 行业板块列表：`fs=m:90+t:2`；板块成分：`fs=b:BKxxxx`

注意：
- **请求要限速**。同一域名连续快速请求会被封；批量抓取之间留间隔。
- 抓回来的数**不要直接当结论**，先说明来源与时间。
- 需要长期重复使用的数据，优先用 `quant_data_sync` 同步到本地，而不是每次现抓。

## 指数与行业成分

`quant_industry_stocks` / `quant_index_constituents` 依赖东财板块 fs 语法，
**该语法未在 P1 单独验证过**，可能失败。失败时按上面的方式用 `web_fetch` 兜底，
不要静默返回空列表。

v1 **未接入指数行情**：回测的基准默认是"区间内等权买入持有代理"，
结果里会写明这一点。需要真实指数基准时要明确告知用户这个限制。
