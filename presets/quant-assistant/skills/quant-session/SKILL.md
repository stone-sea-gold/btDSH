# 会话机制：goal / fork / 压缩

这三件事都不是量化算法，但它们决定**一次长研究会话能不能活下来**。
量化任务的典型形状是「试很多次、每次结论都要留着」，这恰好是最容易被这三件事毁掉的形状。

## 1. goal：把"一个长目标"钉在会话上

`goal` 是**会话级的目标对象**，会跨轮次持续存在，并在被 disarm 后仍可通过"继续"重新激活。

### 什么时候开

**开**：
- 用户给的是一个**需要多轮才能完成**的目标，例如"把沪深300的动量策略做到能用的程度""帮我把这套因子体系补全并验证"
- 用户明确说"慢慢来""不用一次做完""做到 XX 为止"

**不开**：
- 一次问答就能答完的（"这只股票近一年波动率多少"）
- 用户只是让你跑一次回测
- 日常单轮工作

**不要为了显得认真而开 goal。** 它会让每一轮都带上目标上下文，单轮任务上纯属噪声。

### 怎么用

```
create_goal {objective: "..."}     # objective 要写"完成"的判据，不是"方向"
get_goal                           # 每次更新前先读，拿到准确的 goal_id 与 revision
update_goal {action: "complete"}   # 只有目标**真的达成**才标完成
```

判据写法：

- ✅「用 momentum_1m 在 2019–2024 全市场做月度 Top20 回测，样本外 2025 单独复核，导出报告」
- ❌「研究动量策略」

后者永远无法判定完成，模型会一直挂着它。

### 纪律

- **完成要如实**。跑通了主路径、但样本外还没复核 → 那不算完成。
- **blocked 只在同一个阻塞条件连续 3 轮不变时用**，且必须在 `blocked_reason` 里写清那个具体条件。
  "还没做完""有点难"不是 blocked。
- 会话被 resume / fork 之后 goal 是 **disarmed** 状态。用户说"继续"时，先 `get_goal`，
  再用 `update_goal {action:"resume"}` 重新激活。

## 2. fork：用一个"没看过答案"的上下文做独立复核

`subagent_fork` 会开一个子会话，**继承当前对话到此刻为止的历史**，然后独立往下做。
它看不到你之后说的话，也看不到你之后的发现。

### 量化里唯一真正值得用它的场景：样本外复核

这是本 preset 反复强调的纪律——参数扫描是**样本内择优**，必须样本外复核。
而"自己复核自己"有个天然缺陷：**你已经知道样本内的最优参数和它的漂亮数字了**。

fork 恰好解决这一点：在**看到样本内结果之前**分叉，让子会话独立挑参数、独立在另一段区间上跑，
再回来对答案。两个数字对不上，说明策略不稳；对上了，可信度才真正提高。

```
# 在跑样本内扫描**之前**分叉
subagent_fork {
  prompt: "独立做一件事：用 momentum_1m 在 2025-01-01~2026-09-21 上做月度 Top20 等权回测，
           自己决定 topK 与调仓频率，不要参考任何样本内结论。报告总收益、年化、最大回撤、
           夏普，并说明你选这组参数的理由。"
}
```

### 不要用它做什么

- **不要**用它并行跑一堆回测来"加速"。回测是 CPU/磁盘密集的本地计算，
  子会话并不更快，而且每个子会话都要重新读同一份数据仓库。
- **不要**用它做需要用户确认的事——子会话里的工具拒绝同样需要人来放行，链路更长。
- **不要**在 fork 里做全市场同步。数据仓库是**同一个**，并发写入只会互相干扰。

### 纪律

- fork 出来的结论要**如实标注来源**（"这是独立分叉会话给出的数字"），不要把子会话的结论说成自己的。
- 分叉点要在"看到答案之前"。跑完样本内再分叉，就等于没分叉。

## 3. 压缩：它会悄悄吃掉你的证据

`compaction-basic` 会在上下文变长时压缩历史；`compaction-tool-result-pruner` 还会在
**工具结果超过 8KB 时**做头/中/尾裁剪。量化会话的两种结果恰好最容易超限：

| 结果 | 典型大小 | 压缩后会怎样 |
|---|---|---|
| 回测的完整净值曲线（1800+ 点） | 几十 KB | 被裁掉中段，**曲线不再完整** |
| `quant_factor_preview` 的因子值明细 | 视 topN | 明细被裁，只剩头尾 |
| `quant_data_status` 的面板列表 | 小 | 基本不受影响 |

### 唯一的正确做法：先落盘，再依赖

**任何你打算在后面引用的结果，先用 `quant_export` 落成文件。** 文件不受压缩影响。

```
quant_backtest_run {...}                       # 跑出结果
quant_export {kind: "backtest", backtestId}    # 立刻落盘
present {files: [...]}                         # 交给用户
```

之后即使对话被压缩，你仍然可以：

- `quant_backtest_get {backtestId}` 重新取回留档结果（回测结果本来就存在本地库里）
- `quant_export` 导出的文件仍在磁盘上

### 所以

- **不要**在回复里"凭记忆"重述一个已经不在上下文里的净值曲线或明细表。
- 不确定某个结果还在不在上下文里 → 用 `quant_backtest_get` / `quant_export` 重新取，
  而不是猜。**猜测数字是本 preset 里最严重的错误之一。**
- 长会话里主动落盘，不要等被压缩了才想起来。

## 一句话总结

| 机制 | 什么时候用 | 一句话纪律 |
|---|---|---|
| `goal` | 多轮才能完成的目标 | 判据要可判定；完成要如实 |
| `subagent_fork` | 样本外独立复核 | 必须在看到答案之前分叉 |
| 压缩 | 一直存在 | 要引用的结果先 `quant_export` 落盘 |
